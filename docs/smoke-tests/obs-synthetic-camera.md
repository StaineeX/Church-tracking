# OBS synthetic-camera smoke test

This is a manual OBS runtime check. The unit/layout suite and CI plugin build do not prove that OBS loaded the module or that the preview behaved correctly. Use a host with OBS Studio, a working display/graphics backend, and the built `church-director` plugin installed in OBS's module search path with its effect and locale assets. No camera, detector model, or cloud account is needed.

1. Start OBS with a **clean profile** and a new, empty scene collection. Record OBS version, operating system, plugin commit, build preset, install prefix, and whether the plugin loaded. Do not reuse a service profile. Keep the OBS log from this launch.
2. Add a deterministic **test pattern** as an OBS Image source: use a local, static 1920×1080 PNG with a contrasting grid and numbered corner/center markers. Set the canvas to 1920×1080 and leave the Image source at its native size; do not move it during the test. Preserve the exact PNG (or its checksum and a screenshot) so the visible crop can be compared later.
3. Open that source's Filters, add the Church Director video filter (`church_director_filter`), and leave **Synthetic target mode** enabled. Keep Enabled on, but leave **Tracking armed** off initially. Record the filter settings screenshot. In OBS Settings → Hotkeys, assign a shortcut to the **Toggle Church Director tracking** action listed under that source. This is the shortcut to map to the physical PTZ controller button or its Windows macro software.
4. With tracking disarmed, watch the preview for at least 5 seconds. It must remain the unmodified full source and the log must not show detector work. Press the assigned hotkey once: the filter must log `tracking ARMED`, acquire the synthetic target, and produce a visible initial zoom-in ramp followed by continued pan motion and continued crop motion across the fixed pattern. Press it again: it must log `tracking DISARMED`, return to the full source, and stop submitting frames. The visible region must remain within the source bounds and the pattern must never turn black, freeze, or expose outside pixels. Capture screenshots before arming, during the ramp, while armed, and after disarming. If motion is hard to see, increase Max zoom above 1.0; Minimum zoom is fixed at 1.0 in this milestone.
5. **Disable** the filter, remove it, and **re-add** it. Repeat this arm/disarm and disable/remove/re-add cycle **three times**. After each cycle, verify that OBS remains responsive, a disarmed filter is full-frame, and a newly added filter starts disarmed. Close OBS normally and check the log for unload/shutdown errors, hangs, and crop-effect errors.

Preserve the exact OBS log for the test launch (`Help → Log Files → View Current Log File`, then save it), the OBS version/build and plugin commit, the built module and installed effect/locale paths, the filter-settings screenshot, the test-pattern file or screenshot, and preview video or timestamped screenshots. Record each cycle's result and any `Church Director` warnings/errors. A passing runtime result requires both visible behavior and clean repeated shutdown; a green CTest run is only **unit/layout** evidence.

If OBS cannot run, mark the **OBS runtime smoke test unavailable** and state the exact failing check and scope: for example `OBS executable absent`, `plugin not built because libobs development files were absent`, `plugin not listed in OBS Filters`, or `graphics/display backend unavailable`. Attach the command or UI observation and diagnostic/log, with platform, OBS version if known, plugin-build status, and which of steps 1–5 were not attempted. Do not mark pan/crop/zoom or cleanup as passed without observing them in OBS. Likewise, if the plugin build itself is unavailable, report its configure/build command and exit code separately from any passing unit/layout tests.
